## Принцип работы с неопределёнными мерами

176 позиций содержат осмысленную переменную меру: долить, по вкусу, для украшения или по необходимости. Они не заменены выдуманными миллилитрами. Среди них есть не только украшения: например, исходный Zoksel не задаёт пропорции вообще, Figgy Thyme не задаёт объём лимонного сока, а Rum Punch — вместимость бутылок. Это явно указано в карточках. Исходные страницы [Zoksel](https://www.thecocktaildb.com/drink/15691-zoksel-cocktail), [Figgy Thyme](https://www.thecocktaildb.com/drink/178344) подтверждают неполноту исходных мер, а не фиксированные пропорции.

Доли, шоты, чашки, кварты, пинты, галлоны и упаковки сохранены без произвольного пересчёта вместимости. Дробные количества целых лимонов/лаймов сохранены как количество фруктов с явным шагом выжимания сока. Такие числовые количества масштабируются калькулятором, при этом не предполагается одинаковый выход сока из каждого плода.

Пунши, домашние ликёры и некоторые смузи являются исходными рецептами на партию. Там, где источник однозначен, размер партии указан в шагах и метаданных; неподтверждённый выход не придуман. Калькулятор умножает указанную основу рецепта. При будущей нормализации партий до одного бокала нужно отдельно учитывать выход сиропов и концентратов.

`repair_catalog.mjs` сохраняет явные редакторские решения этой миграции. Это обслуживающий инструмент, не код приложения; при будущих редакторских изменениях его нельзя запускать автоматически поверх нового каталога. Приложению не нужны сервер, платный API или сетевой запрос для этих данных.
